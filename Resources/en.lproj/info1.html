This demo searches 300,000 texts by meaning and shows what the 4D vector index changes.

What are embeddings?
An embedding is a vector of numbers that represents the meaning of a text: texts with similar meaning produce close vectors, even when they share no word.

How does this demo work?
- Every text of the corpus is embedded with the local ruri-v3-310m model (a llama-server started by the llama-cpp component, no API key needed) and stored in a 4D.Vector field.
- The same vector is stored twice: once in IndexedVector (covered by a cosine vector index) and once in NonIndexedVector (no index).
- The sample prompts are stored in English and Japanese, each with its own query vector, so the search runs in the language of the UI.
- A search embeds the prompt with the query prefix and runs a single ORDA query:
ds.Data.query("IndexedVector>=:1 order by IndexedVector desc"; param)

What do I need?
4D 21 R5 or later. The embedding model runs locally: the llama-server binary ships with the llama-cpp component and the model file is expected in ~/.GGUF/ruri-v3-310m-GGUF/ (see the README).
